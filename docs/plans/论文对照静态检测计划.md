# 外部数据集反哺静态检测计划（MalSkillBench / MCPTox / SkillTrustBench）

> **状态：P0 已完成（2026-09-17），P1 待启动**（2026-09-17 拟；同日完成论文核实与数据获取，见 §2 与 P0）。定位：用公开恶意数据集的分类体系与样本，
> 反向强化 `solution/` 资产采集器与风险标注（generic 层），并建立**靶场之外的泛化回归证据**。
> 范围只覆盖赛题**能力 1（静态资产风险识别）**；能力 2（运行时检测阻断）不受本计划影响。

## 0. 结论摘要

- **动机**：我们的静态规则源自 AgentRange 一个靶场的恶意件逆向，官方 oracle 内指标满分
  恰是"靶场特化"的证据；赛题要求"**一套通用算法**"，当前缺少靶场之外的验证。
- **做法**：吸收公开数据集的恶意维度 taxonomy → 对照 `solution/rules/generic/` 找空白 →
  补规则/采集字段；同时把数据集样本转成 fixture + oracle，复用现成的 `solution/targets/bench.py`
  评测机制出**外部检出/误报数字**。
- **成本**：约 1 周（P0–P4 五个阶段），不碰 Docker、不建新靶场、不引入新依赖。
- **产出**：① 恶意维度对照表；② generic 层新增规则；③ 外部回归基线数字与逐条归因；
  ④ 报告"通用性"论证段落。原靶场 oracle、两个留出集、guard 指标全部作为**回归门禁不回退**。
- **已砍掉**：此前讨论的"自生成攻击链数据框架"（轨迹 IR / 模板引擎 / LLM-judge 闭环），
  工程量大、周期风险高，本计划用更低的成本拿到"通用性证据"这条主线。

## 1. 背景与定位

1. 现状：`rules/generic/`（`advisories.yaml` + `patterns.yaml`）与 `profile/agent-range.yaml`
   分层已落地（P3，2026-09-15），`--generic-only` 可单独出成绩；两个留出环境
   （`simulated-target`、`agent-asset-lab`）oracle 满分。但三个环境的恶意样本本质同源
   （都由我们/队友按靶场风格构造），仍是"自建基线互证"。
2. 公开数据集提供两样我们没有的东西：
   - **维度体系**：从数千样本归纳的恶意行为 taxonomy（MalSkillBench 108 格、
     SkillTrustBench 9 类 × 5 层依赖、MCPTox 投毒模板族），系统性暴露我们规则的盲区；
   - **外部样本**：非我们构造的恶意/良性 skill 与 MCP 样本，转成 oracle 后就是
     独立于官方靶场的第三方评测集。
3. 与既有计划的关系：
   - 是《[融合与测试计划](融合与测试计划.md)》阶段 2"泛化合流"的**横向扩展**
     （留出集是第二、三环境，外部数据集是组件级样本集，互补不重复）；
   - 数据源登记并入《[oss-ranges](../modules/oss-ranges.md)》台账纪律：
     第三方无明确 license 的项目只做外部参考，**不进入发布物**。

## 2. 数据集与论文核实对照

> arXiv 条目均已于 2026-09-17 对照原文摘要核实；数字以核实结果为准，与此前调研摘要有出入处已修正。

### 第一梯队（维度吸收 + 样本回归，本计划主体）

| 数据集 | 出处 | 构成 | 关键信息对照 |
|---|---|---|---|
| **MalSkillBench** | [arXiv:2606.07131](https://arxiv.org/abs/2606.07131) v3、[GitHub](https://github.com/lxyeternal/MalSkillBench) | 3,944 恶意 skill（3,214 闭环生成 + 703 野生）+ 4,000 匹配良性；三维 taxonomy 108 格 | ① 生成即验证：Docker 沙箱 + syscall 监控 + LLM judge，只收真实"打火"样本；② 野生样本偏斜：86.6% 为单一加密窃取、81% 出自两个账号；③ 最强检测器代码注入 recall 98.4%，prompt 注入与 agent 控制面失效；④ 结论：须联合推理"意图+代码+指令"，单一视角各看一半 |
| **MCPTox** | [arXiv:2508.14925](https://arxiv.org/abs/2508.14925)（AAAI 2026，Proc. 40:35811–35819） | 45 个真实在线 MCP server / 353 工具；3 类投毒模板 few-shot 生成 1,312 用例；10 类风险 | ① 投毒藏在工具元数据、无需执行即可生效；② 20 个 LLM 全部易感（o1-mini ASR 72.8%），模型越强越易中招；③ 拒绝率最高 <3%；④ 数据在匿名仓库开源（`anonymous.4open.science/r/AAAI26-7C02`，Cloudflare 盾，自动抓取受阻，见 P0 结论） |
| **SkillTrustBench** | [腾讯 Matrix](https://matrix.tencent.com/skilltrustbench/)（官方页自述，非论文） | 5,520 样本、9 攻击类别、5 层 agent 依赖 | 评测定位与我们资产风险识别相同（评恶意 skill 扫描器）；5 层依赖链投毒是我方空白维度 |

### 第三梯队（轨迹级，本计划不用）

- **STAC**（[arXiv:2509.25624](https://arxiv.org/abs/2509.25624) v3）：单步无害、组合有害的工具链攻击；483 案例（1,352 组交互）由"合成 → 环境内执行验证 → 逆向工程诱导 prompt"闭环生成；8 个 agent 平均 ASR 91.2%；结论"防御须推理整个动作序列的累积效应"。对能力 2（guard/链路还原）是引证，不进本计划执行面。
- **DiagChain**（[arXiv:2608.03591](https://arxiv.org/abs/2608.03591) v1，**已核实，定位纠偏**）：评测"LLM agent 从 telemetry 重建攻击链"的能力（SOC 方向），**不是 agent 攻击数据集**；69 场景 / 849 参考步骤 / 5 个阶段级指标，最强配置仅完成 39.6% 步骤。仅借鉴其阶段级指标设计（能力 2 用），不提供恶意组件语料。
- R-Judge / AgentDojo / ASB：运行时轨迹类，维持原判，不在本计划展开。

## 3. 与现状的对接点（为什么不贵）

| 现成机制 | 复用方式 |
|---|---|
| `solution/rules/generic/` + `--generic-only` | 新维度全部落 generic 层，与靶场特化隔离；沿用字面量黑名单测试纪律 |
| `solution/targets/bench.py`（统一适配两种 oracle 格式，TP/FN/FP/extra + `not_measured`） | 新数据集只需两步：样本落成 fixture 目录、标签转成 oracle YAML，即挂进现成评测 |
| `simulated-target` / `agent-asset-lab` 留出集 | 外部数据集 fixture 作为**第三类测试目标**（组件级样本集，区别于环境级） |
| `reference/oss-ranges/` 台账 | 新引入的数据源按既有格式登记来源与 license 状态 |
| 队友 agent-scanner（peer 引擎） | 同一批 fixture 也可喂给 peer 引擎跑分，多一组"双引擎互证"证据 |

### P1 恶意维度对照表（1–2 天，可按数据集并行分工）

- 盘点 `rules/generic/patterns.yaml` + `advisories.yaml` 现有规则实际覆盖的特征
  （含采集器喂给规则的字段面）。
- 提取三家 taxonomy 到统一粒度，逐格对照，产出**维度对照表**：
  *维度 × 来源数据集 × 我方现状（已有规则 / 需新增 / 需采集器增强 / 静态不可检 / 超范围）*。
- **验收**：第一梯队 taxonomy 的每个顶级维度在表中有明确归属，无"未评估"残留。

### P2 规则与采集器增强（2–3 天）

- "需新增"维度：写 generic 规则（谓词 + 证据字段），每条规则带来源数据集标注。
- "需采集器增强"维度：改 `solution/collectors/` 对应通道（预期候选：skill 依赖链、
  不可见字符/Unicode 隐写、工具描述跨字段注入——以 P1 对照表为准，不预写死）。
- "静态不可检"维度（纯语义/组合恶意）：记录为运行时职责边界，写入文档而非硬造规则。
- **验收**：新增规则单测；`test_generic_blacklist.py` 黑名单扩充后仍全绿
  （通用层不得混入任何靶场字面量）。

### P3 外部回归与基线（2–3 天）

- 样本转 fixture 目录（恶意 + 良性分开），标签转 oracle，接 `bench.py` 出四项指标。
- 对未命中恶意样本**逐条归因**（缺规则 / 采集不到 / 静态边界 / 样本标注噪音），
  能修的回 P2 迭代，修不了的记录。
- 同批 fixture 喂 peer 引擎对跑一次，记录双引擎差异。
- **验收**：产出基线数字与归因表。**首跑不预设阈值**——外部数据集是自证的泛化证据，
  不是赛题指标口径；数字如实记录（沿用 `not_measured` 诚实口径文化）。

### P4 报告并入（0.5 天）

- 报告"通用性"论证段落：维度对照表 + 外部基线数字 + 双引擎互证，
  与留出集、`--generic-only` 成绩共同构成通用性证据链。
