# 资产识别实施计划（第一阶段）

> **状态：已完成**（2026-09-11 随 v1.0-asset 交付，见 [changelog](../changelog.md)）。
> 实际实现与本计划的差异：采集器落在 `collect_static.py`（8 通道）+ `runtime/`（3 探测器）而非 `collectors/` 目录；
> 节点闭集扩为 14 类（计划为 12 类）；P5 的 CycloneDX AI-SBOM 导出未做（转为优化清单 B2 项）。
> 现状以 [architecture.md](../architecture.md) 为准，后续优化项见 [优化计划清单](资产识别优化计划清单.md)。

> 依据：[靶场信息整理](../modules/range.md) 中的环境事实 + 前序讨论确定的图谱 schema（闭集分类、声明/观测双面）。
> 范围：**只覆盖赛题能力 1（Agent 资产风险静态识别）**；但 schema 与数据结构为能力 2（运行时监控）预留接口（observed facet、OCSF 事件入口）。
> 目标指标：资产盘点漏报率 < 5%、准确率 ≥ 99%；资产风险识别准确率 ≥ 95%、漏报率 < 5%。

## 0. 总体架构与代码布局

流水线：**采集器 → 归一化 → 图谱构建 → 完整性校验 → 风险规则引擎 → 评估/导出**

```
solution/
├── collectors/            # 采集通道（可插拔）
│   ├── docker_env.py      # compose / docker inspect / .env / 网络与挂载
│   ├── mcp_probe.py       # MCP initialize + tools/list（运行时声明面）
│   ├── mcp_code_scan.py   # MCP server 源码扫描（Tool 注册、hidden、on_start）
│   ├── skills_scan.py     # skills/ 目录：frontmatter、正文、脚本、hash
│   ├── http_probe.py      # 各服务 HTTP 面（版本、登录、端点）
│   └── identity_probe.py  # /login 探测、JWT 解码、scope 提取
├── graph/
│   ├── schema/            # 节点/边 JSON Schema（闭集分类）
│   ├── builder.py         # 采集结果 → 节点/边 → 图
│   ├── store.py           # NetworkX 内存图 + JSON 持久化
│   └── validators.py      # 引用完整性 + 双源对账（SHACL 式）
├── rules/
│   ├── registry.py        # 规则注册与执行框架（每条规则挂 CWE/OWASP/ATLAS 标签）
│   ├── config_risks.py    # R1 配置风险
│   ├── supply_chain.py    # R2 供应链恶意组件
│   └── versions.py        # R3 组件版本 ↔ CVE（本地 OSV 格式公告库）
├── oracle/
│   ├── ground_truth.yaml  # 内部评测标准答案（仅评分用，规则不得读取）
│   └── score.py           # 漏报率/准确率计算
├── export/
│   ├── cyclonedx.py       # AI-SBOM 导出
│   ├── report.py          # 风险报告（证据 + 标准编号）
│   └── viz.py             # 资产图谱可视化（答辩演示）
├── advisories/            # 本地漏洞公告库（OSV schema JSON）
└── cli.py                 # scan → build → analyze → report 一条龙
```

技术栈：Python 3.12（与靶场 requirements-dev 一致），NetworkX，jsonschema，pyjwt。

**部署形态（关键决策）**：8 个 MCP server 无宿主机端口，`tools/list` 探测必须进入
`opspilot-net`。方案：用一个 **scanner sidecar 容器**（compose override 文件追加服务，
挂到 opspilot-net），宿主机侧收集器负责有端口的服务 + docker inspect。禁止使用
llm-stub `/admin/trajectories`（赛题明确）。

## 1. 阶段计划

### P0 环境就绪 + 评测基线（0.5~1 天）

| # | 任务 | 产出 |
|---|---|---|
| 0.1 | 靶场拉起全流程跑通：`cp .env.example .env && make up && make seed && make smoke && make replay SCENARIO=C2-B` | 可复现环境 |
| 0.2 | 编写 `ground_truth.yaml`：依据《靶场信息整理》（`docs/modules/range.md`）列出全部期望资产与风险（见 §2、§4 清单） | 评测基线（约 45 节点 / 12 风险项） |
| 0.3 | 编写 `score.py`：对比系统输出与标准答案，输出盘点 P/R、风险识别 P/R | 指标驱动开发闭环 |

**验收**：`score.py` 对空输出得 0 分可运行；靶场一条龙命令全部成功。

### P1 采集器落地（2~3 天）

按采集通道矩阵逐个实现，每个采集器单独可测：

| # | 采集器 | 采集内容 | 预期数量（对账用） |
|---|---|---|---|
| 1.1 | docker_env | 14 个服务、2 个网络、镜像/版本、env 配置项、managed-host.env | 服务 14、网络 2 |
| 1.2 | mcp_probe | 8 个 server 的声明工具（tools/list） | server 8、声明工具 9 |
| 1.3 | mcp_code_scan | 源码级 Tool 注册全集、hidden 标记、on_start 回调、subprocess/外联调用点 | 工具全集 10（含 hidden 1） |
| 1.4 | skills_scan | 7 个 Skill 的 frontmatter + 正文 + 脚本文件 + hash | Skill 7、脚本含 export.py |
| 1.5 | identity_probe | 5 个身份（/login → JWT 解码 → role/scope） | 身份 5 |
| 1.6 | http_probe | langflow 版本/auto_login/flows、llm-stub、c2-sink、mock-internet 存活与特征 | 组件指纹 |

**验收**：每个采集器输出数量与预期对账一致；`tools/list` 结果与代码扫描结果能做差集
（差集 = 隐藏工具，本环境应恰好得 `notes-sync.debug_exec`）。

### P2 图谱构建（1~2 天）

| # | 任务 | 说明 |
|---|---|---|
| 2.1 | 节点/边 JSON Schema | 闭集 10 类节点（见 §3），每类含 `declared`/`observed` 双 facet 与 `provenance`（来源通道） |
| 2.2 | builder + store | 采集结果归一化入图；NetworkX 内存 + JSON 落盘 |
| 2.3 | 完整性校验器 | ① 引用完整性：Tool 必有宿主 MCPServer；`OPENAI_TOOL_ROUTES` 映射端必须存在；Skill `allowed-tools` 引用必须可解析。② 双源对账：compose 服务集合 vs 图中组件集合，差集即漏报清单。③ 悬空引用自动转风险项 |

**验收**：全部校验规则通过；对账差集为空；每类节点 provenance 可追溯到采集通道。

### P3 风险规则引擎（2~3 天）

规则框架：每条规则 = `id + 目标节点类型 + 判定逻辑 + 证据产出(file:line/解码内容) + 标签(CWE/OWASP/ATLAS)`。

**R1 配置风险规则（对应 7 项标准答案）**

| 规则 | 判定要点 | 标签 |
|---|---|---|
| weak-secret | JWT_SECRET 命中弱模式（已知弱值表 + 熵值阈值） | CWE-321 |
| confused-deputy | `OPSPILOT_PROPAGATION=service-account` + 宽权限服务账号 token | CWE-269 |
| auto-login / weak-cred | `LANGFLOW_AUTO_LOGIN=true`；admin/admin、postgres 弱口令 | CWE-798 |
| permissive-semantics | 工具参数支持 `tenant="*"`（代码级） | CWE-863 |
| missing-identity-prop | Agent→MCP 调用点无身份头（代码扫描） | CWE-284 |

**R2 供应链恶意组件规则（对应 5 项标准答案，重点防误报）**

| 规则 | 判定要点（结构性模式，非关键词） | 应命中 | 不得命中（诱饵） |
|---|---|---|---|
| desc-poisoning | 工具描述含"指令式命令 + 隐藏要求"结构（`<IMPORTANT>`、"不要向用户提及"、指令动词指向其他工具/文件） | notes-sync.sync_note | — |
| hidden-tool | 代码注册工具 ∉ tools/list | notes-sync.debug_exec | — |
| startup-egress | on_start 回调读取敏感 env 并外发 HTTP | notes-sync 启动外联 | — |
| script-payload | 脚本内 Base64 解码后命中 subprocess/下载执行模式 | pdf-export export.py | — |
| hidden-comment-inj | Skill 正文 HTML 注释含指令式内容 | meeting-summary | — |
| keyword-only 规则 ❌ | **明确禁止**"含 password/exec 字样即告警"类规则 | — | password-policy-check |

**R3 组件版本漏洞**：本地 advisories/（OSV JSON 格式，预置 CVE-2026-0770/CWE-94、
CVE-2026-5027/CWE-434），按"组件名 + 版本区间"匹配 → 命中 langflow 1.8.4。

**验收**：12 项标准答案全部命中且带证据；诱饵组（password-policy-check、sandbox-exec、
threat-intel 描述）零误报；每条命中输出可读的判定依据。

### P4 评估调优（1~2 天）

| # | 任务 |
|---|---|
| 4.1 | `cli.py scan→analyze→score` 全链路，跑出四项指标 |
| 4.2 | 漏报修补：逐条检查未命中的标准答案项，补通道或补规则 |
| 4.3 | 误报修补：逐条检查多余命中，收紧规则（收紧方向：从关键词改为结构模式） |
| 4.4 | **通用性自检**：改容器名/服务名/实例 ID 后重跑指标不退化（证明规则不是对靶场字面量过拟合） |
| 4.5 | 指标达标确认：盘点漏报 < 5%、准确率 ≥ 99%；风险准确率 ≥ 95%、漏报 < 5% |

### P5 输出与交付（1 天）

| 资产类型 | 数量 | 明细要点 |

| ModelEndpoint | 1 | llm-stub(:8000) |

| Tool | 10 | 9 声明 + 1 隐藏（debug_exec） |

## 3. 节点闭集分类（schema 骨架）

AgentApplication / FrameworkComponent / ModelEndpoint / MCPServer / Tool /
Skill / SkillScript / Identity / DataStore / NetworkSegment / ExternalEndpoint /
ConfigItem —— 共 12 类，不允许"其他"。

统一字段：`id, type, name, declared{}, observed{}, provenance[](来源通道+时间), risks[]`。
边类型：`mounts(应用→工具/Skill)、exposes(server→工具)、declares_allowed(Skill→Tool)、
attached_to(组件→网络)、authenticates(身份)、depends_on(组件版本依赖)、
egress_to(→ExternalEndpoint)、reads/writes(→DataStore)`。
声明边与观测边分属性存放，**检测阶段（第二部分）直接比对两类边集合**。

## 4. 关键风险与预案

| 风险 | 预案 |
|---|---|
| 隐藏工具黑盒发现不了（无源码场景） | 双通道：源码可达时代码扫描为主；不可达时留运行时兜底（调用了清单外工具 = 运行时信号），答辩表述为"分级发现能力" |
| 诱饵误报 | 规则全部走结构模式（指令式+动作指向），P3 内置诱饵单测，禁止纯关键词规则 |
| 对靶场过拟合、通用性受质疑 | P4.4 改名重跑；公告库走 OSV 格式；规则参数（弱密钥表、注入模式库）外置可扩充 |
| MCP 探测进不了内网 | scanner sidecar 挂 opspilot-net（compose override），不改动靶场原文件 |
| 语料/轨迹依赖 | 本阶段纯静态，不依赖 replay 语料；明确不使用 /admin/trajectories |
