### A. 采集器（5 项）
- A1 插件化+路径泛化：CollectorRegistry（applies_to/run），L1 通用通道与 L2 靶场模式分层，collect_static 变兼容入口——通用性叙事的核心防御（2 天）

- A3 sidecar 黑盒探测：替代 docker exec 注入，覆盖"源码/容器不可达"场景（1 天）
- A4 docker inspect 观测源：运行时实测 vs compose 声明，双源对账升级三源（0.5 天）
- A5 identity_probe 用户自动发现：去硬编码 USERS（0.5 天）

### B. Schema 设计（5 项）
- B1 分类型收紧：per-type declared 字段白名单、provenance minItems、渐进 additionalProperties:false（1 天）
- B2 **CycloneDX AI-SBOM 导出**（P5 欠账，答辩可视化交付物，0.5 天）
- B3 OCSF 事件 schema：guard.jsonl 规范化，能力2 融合接口（0.5 天）
- B4 STIX 2.1 攻击链导出：E1 的输出载体（1 天）
- B5 schema 版本化策略（$id/version/兼容说明，0.25 天）

### C. 图谱展示（5 项）

- C2 攻击路径高亮：后端 /api/path（k 短路）+ 前端染色（1 天）
- C3 declared/observed 边视觉区分 + provenance 筛选器（0.5 天）
- C4 BOM 漂移 diff 视图：复用 bom/diff.py 前端化（1 天）
- C5 导出：PNG / GraphML / 工件下载（0.5 天）

### D. 风险检测证明（6 项）
- D1 oracle 接入 cli verify：跑出四项 P/R 指标（oracle 已有，接线 0.25 天）
- D2 **通用性自检**：改名/换端口重跑指标不退化——"防过拟合"的实证（0.5 天）
- D3 变异语料库：程序化生成恶意变体（新投毒描述/新隐藏工具/新混淆载荷）测规则召回，复刻 BOM 变异测试思路到扫描器本身（1.5 天）
- D4 诱饵回归语料扩充（0.5 天，可持续）
- D5 规则×GT×CWE/ATLAS 覆盖矩阵工件（GROUND_TRUTH_MAP 已有雏形，产品化 0.5 天）
- D6 幂等性测试：同输入两次扫描 → 图哈希一致（0.25 天）

### E. 图谱推理（4 项）
- E1 **攻击路径推理**：污染源（WebPage/Skill 注入）→ 敏感资产（db/egress）的 k 短路径 + 风险加权，输出接 B4 STIX——"还原能力"从记录式升级为推理式（1.5 天）
- E2 风险传播打分：节点种子分沿边传播（与运行时加性模型同构的静态版）（1 天）
- E3 可达性/爆炸半径：身份 X 在 scope 约束下的可达资产集、越权可达路径枚举（1 天）
- E4 ENV 规则声明化：12 条硬编码规则 → 数据驱动注册表（条件+遍历模式+标签），可扩展且答辩好讲（1 天）

### F. 图谱安全约束（5 项）
- F1 约束声明化：validators 硬编码 → constraints.yaml（SHACL 式数据文件），与 rules.yaml 外置对称（1 天）
- F2 策略即代码：从图生成 least-privilege 机器可读建议（scope 收窄/工具白名单/egress 白名单）→ policy.json，闭环到 guard 基线（1 天）
- F3 工件防篡改：scan/graph/bom 哈希 manifest（呼应 tamper-evident-logging 控制族）（0.5 天）
- F4 provenance 强制非空 + 无源节点告警（0.25 天）
- F5 CI 门禁：scan→validate→test 一键门禁脚本，工件违规即失败（0.5 天）
